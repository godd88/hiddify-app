# Hiddify 5.5.5 全平台精简方案

## 基线

从 `v5.5.5` 创建独立分支。所有平台共用这次界面和功能调整。

## 实施范围

- 移除应用内更新，包括启动延迟检查、手动检查、商店分发版本中的应用内提示，以及应用自带的下载和安装流程。清理专用依赖、原生接口和权限。商店和系统继续管理外部更新。
- 删除窄屏「设置 → 关于」入口及其子路由，并删除宽屏导航项及其独立路由。同步清理焦点和导航索引。同步移除 macOS 原生应用菜单中的「关于」。版本信息、复制版本信息、打开工作目录及页面内链接随页面一起移除。
- 沿用 5.5.5 的地区 GeoSite、GeoIP 规则集地址、配置及核心刷新机制。保留配置订阅自动更新。
- 主页标题栏中，`Hiddify` 旁的版本标签改为纯文本 `www.we2say.com`。应用打包版本为 `5.5.5+50505`。
- 共用的配置导入面板移除「免费」「帮助」及面板内的免费列表。粘贴、文件导入、手动输入、移动端扫码和电视端手机导入继续可用。已导入的免费配置仍可使用。
- 无选中配置时，点击「点击连接」直接打开与「+」相同的底部导入面板。导入成功后可再次点击连接。已有选中配置时沿用原连接流程。

## GitHub Actions 构建

fork 的 `feat/5.5.5-slim` 分支推送触发 `Fork build`。工作流使用 Flutter `3.38.5`，重新编译精简版 Flutter 应用及各平台外壳。各任务通过现有的 `make <平台>-prepare` 下载官方预编译的 `hiddify-core v5.5.5`，校验固定的 SHA-256 后再解包。无需检出核心子模块或提交二进制文件。[官方核心归档](https://github.com/hiddify/hiddify-core/releases/expanded_assets/v5.5.5)

| 平台 | 构建目标 | 产物 |
|---|---|---|
| Android | `android-apk-release` | 通用 APK，使用 runner 的调试签名 |
| Windows x64 | `windows-zip-release` | 便携 ZIP |
| Linux x64 | `linux-release` | DEB 和 AppImage |
| macOS Intel / Apple Silicon | `macos-release` | 通用 DMG，使用临时签名和本地 VPN helper |

四个平台并行构建，任一平台失败时其他任务继续。工作流使用 `contents: read`，仅上传 Actions Artifacts，每个平台的产物名包含平台、架构和提交短 SHA。独立的 Ubuntu 24.04 任务运行 Flutter 静态分析和测试，使用该系统的 SQLite 运行数据库迁移测试。Linux x64 继续在 Ubuntu 22.04 打包。所有任务检查依赖锁文件。iOS、商店发布和 GitHub Release 独立于此工作流。

1. 在 fork 的 **Actions** 页面启用工作流。提交精简版改动和工作流后，执行 `git push -u origin feat/5.5.5-slim`。
2. 打开 **Actions → Fork build → 对应运行记录 → Artifacts**，下载四个平台的产物。Windows 解压后运行。Android 若已安装同包名的官方版，先备份配置，再卸载官方版并侧载 APK。

## 验收

- 运行静态分析及相关 Flutter 测试。在 Android 和桌面端覆盖窄屏及宽屏，验证旧「关于」地址已失效，其余导航正常。
- 用 fork 产物验证非商店分发版本，并单独验证商店分发版本。启动超过原有的 20 秒后，确认应用没有版本检查请求或更新弹窗。
- 用同一地区配置验证原版及精简版的规则集下载和自动刷新，并验证配置订阅自动更新。
- 在 Android 和桌面端检查主页网址完整可见。分别通过「+」和无配置时的连接按钮进入导入面板，验证「免费」「帮助」和提示框已移除，并检查关闭面板、导入后连接及已有配置直接连接。
- 如提交 PR，按仓库指南录制 Android 和桌面端的英、波斯语浅色及深色对比视频。
